# AGENTS.md — работа с decision-tests

Инструкция для модели/агента, работающего с этой лабораторией. Окружение полностью
изолированное и самодостаточное: всё, что нужно, лежит в этом каталоге.

## Что это

YAML-спека тестов → раннер → YAML-снимки ответов decision-модели (System One).
Смысл и правила лаборатории — в [README.md](README.md). Коротко: инструмент существует,
чтобы менять **одну переменную** спеки (формулировку, варианты, поле стейта) и видеть,
как сместились веса модели.

## Запуск

```bash
# MODEL обязателен — без него API вернёт ошибку
MODEL=<tag> python decision_tests.py                 # автоскан test/*.yaml
MODEL=<tag> python decision_tests.py <файл-теста>    # один файл
```

- Зависимости — msgspec + PyYAML из `requirements.txt`
  (`python -m pip install -r requirements.txt`).
- Полный прогон = `число стейтов × число вопросов` HTTP-запросов (в текущем шаблоне
  9 × 13 = 117). Закладывай таймаут ≥ 10 минут на модель, не запускай прогон в фоне
  и не прерывай его.
- Один запуск = одна модель. Для сравнения моделей — несколько запусков подряд.

## Ollama API

- Раннер ходит в `POST $OLLAMA_HOST/v1/systemone` (дефолт `http://localhost:11434`).
  Проверка доступных моделей: `curl -s $OLLAMA_HOST/v1/models`.
- Нужен Ollama с **уже скачанной decision-моделью** (System One). Скачивание моделей —
  забота окружения, а не спеки; агент модели не устанавливает.
- Используй только decision-модели: эмбеддинги и обычные чат-модели на
  `/v1/systemone` не отвечают.

## Формат спеки (`test/*.yaml`)

Структуры валидируются msgspec'ом с `forbid_unknown_fields`: лишнее поле = краш, а не
предупреждение. Поэтому:

- корень файла — строго `test:` с полями `states` и `questions`; других секций нет;
- вопрос: `{name, q, answers}` + опционально `type`; `name` уникален в пределах файла;
- `answers`: для `choice`/`noul` — map ключ → описание, для `score` — упорядоченный
  список уровней от низшего к высшему;
- ключи `"true"` / `"false"` / `"no"` / `"yes"` — **только в кавычках**, иначе YAML даёт
  bool и msgspec падает;
- `type`: `choice` (дефолт) | `noul` | `score`. Лимиты API: choice 2–26 вариантов,
  noul 2–10; нарушение = отказ сервера;
- `states`: строка ИЛИ JSON-объект с полями (поля реально влияют на ответы). Strip
  trailing `\n` раннер делает сам.

## Правила редактирования спеки

- **Не усложняй формат.** Не добавляй поля, секции, новые типы вопросов без прямого
  запроса от пользователя. Три типа закрыты: choice / noul / score.
- **Варианты ответов — разнонаправленные**, без синонимических пар (синонимы делят
  массу, выбор становится недетерминированным).
- **Не плоди дубли стейтов** — один тикет в разных формах (строка / объект) допустим
  только как осознанная A/B-пара.
- **Проверку порядка вариантов делай дублем вопроса с новым именем** (`team` →
  `team_rev`), а не изменением порядка в исходном вопросе: порядок — переменная
  эксперимента, менять задним числом нельзя.
- В спеке есть **намеренные негативные кейсы** — не «чини» их:
  - `resolution` — синонимические варианты (deny/decline/ask/clarify);
  - `pizza` — вопрос вне темы;
  - `spam_binary` — бинарный twin пятивариантного `spam` (показывает враньё бинарников);
  - `priority` — вопрос к полю, которого нет ни у строковых, ни у одного из объектов.
- Каждый новый вопрос/стейт должен отвечать на исследовательский вопрос. «Для
  разнообразия» добавлять не надо.

## Результаты (`results/*.yaml`)

- Файл: `results/<имя-модели>.<имя-файла-теста>` (двоеточие в теге модели допустимо
  в имени файла). Перезаписывается целиком при каждом прогоне — **не правь руками**.
- Внутри: `results: {model, source, states: [{state, answers}]}`, `source` — путь до
  файла теста, числа округлены до 4 знаков.
- Сравнение моделей: грузить `yaml.safe_load`, индексировать по паре state/вопрос;
  при сравнении float учитывай округление до 1e-4.

## Анализ

- Для анализа достаточно stdlib + PyYAML; для одноразовых разборов — `python` +
  heredoc, скрипты не коммитить.
- Работай с файлами `results/*.yaml`, а не с выводом процесса: stdout — побочный
  эффект, данные — в снимках.

## Чего не делать

- Не переносить артефакты лаборатории за пределы этого каталога.
- Не удалять снимки в `results/` по своей инициативе — это история наблюдений;
  если пользователь явно попросил очистить результаты — удаление допустимо.
- Не подмешивать в запросы к API ничего кроме спеки (никаких своих промптов поверх:
  `state.strip()` и ровно то, что в YAML — и ничего больше).

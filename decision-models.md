## 1. Что это такое

**Decision model** (также **System One model**) — класс AI-моделей, которые не генерируют
текст, а отвечают на заданные типизированные вопросы о переданном состоянии (state)
распределением вероятностей по заранее объявленным вариантам.

Формальный контракт:

```
вход:  state (текст | JSON | массив | изображения/аудио/видео у мультимодальных)
       questions (1..64 именованных вопроса, каждый: type + instructions + criteria)
выход: по одному распределению вероятностей на вопрос, строго по вашим вариантам,
       + confidence, сформированный по фиксированной формуле
```

Ключевые свойства класса:

| Свойство | Смысл |
|---|---|
| **Дискриминативность** | Модель не пишет строк — она скорит варианты ответа. Выход один тип: discrete probability distribution (Wikipedia о Jev) |
| **Типобезопасность** | Типы и структура выхода определяются заранее; «ошибка типа математически невозможна» (TypeSafe). LLM с JSON-режимом такой гарантии не даёт |
| **Параллельный scoring** | Все варианты всех вопросов оцениваются одним non-autoregressive проходом; автогенерации нет → 40–200× быстрее фронтальных LLM на сопоставимых задачах (claims TypeSafe) |
| **Калиброванные вероятности** | Каждый ответ несёт вероятность; обучение целенаправленно штрафует некалиброванность (Brier loss, RLCD) |
| **Zero-shot над произвольными метками** | В отличие от классических классификаторов — категории задаются в инференсе, без дообучения под каждую метку (Wikipedia) |
| **Независимость вопросов** | Вопросы в одном запросе независимы: ответ одного не является контекстом другого; зависимость — только через второй запрос в коде |

Три базовых типа вопросов (у большинства вендоров; у OpenAI — predicates/choices/scores):

| Тип | Ответ | Как читать |
|---|---|---|
| **`noul`** (да/нет) | `noul` ∈ [0,1] — вероятность «true» | 0.9 — сильное «да»; 0.5 — равновероятно. Это число, не boolean |
| **`choice`** | `choice` (мода), `probabilities`, `confidence` | выбор из 2–26 (у Jev — до 255) названных опций |
| **`score`** | `score` — вероятностно-взвешенное среднее индексов уровней (не округляется!), `legend`, `probabilities`, `confidence` | позиция на упорядоченной шкале-рубрике |

Важно: **`confidence` — это концентрация распределения, а не вероятность правоты.**
В API Ollama: `confidence = 1 − H(p)/ln(N)` (энтропия); в API Jev для choice/noul —
`(p_max − 1/n)/(1 − 1/n)`, для score — через среднее абсолютное отклонение от моды
(Wikipedia). «Вероятность 0.9 не означает, что ответ верен в 90% случаев на ваших
данных» — прямая оговорка в документации Ollama.

Происхождение имён: класс «System One» — по Kahneman (System 1 — быстрое интуитивное
мышление против медленного System 2, то есть LLM); «Jev» — по Уильяму Стэнли
Джевонсу (парадокс Джевонса: рост эффективности ресурса увеличивает его потребление —
ожидание, что удешевление интеллекта взорвёт число применений).

## 2. Откуда класс и таймлайн взрыва

**Родоначельник — TypeSafe AI** (Сан-Франциско, основана в 2024). Основатели: Diogo Almeida
(CEO, ~4 года в OpenAI: RLHF, InstructGPT, ChatGPT, GPT-4), Erik Gafni, Sasha Sheng.
Два года в стелсе; релиз Jev 15 сентября 2026 вместе с раундом **$40M seed** во главе с
DCVC (Forbes называет компанию «$200-миллионным стартапом, который хочет исправить
проблему overconfidence в AI»).

Идея: RLHF делает модели суперчеловеческими в следовании инструкциям, но даёт mode
dropping, overconfidence и ненадёжность → LLM требуют human-in-the-loop. TypeSafe пошла
«в противоположном исследовательском направлении»: новая архитектура, параллельный
sampler, новый алгоритм обучения — **RLCD (Reinforcement Learning for Calibrated Decisions)**,
исключительно на синтетических данных. Архитектура, веса и техническая бумага Jev
**не опубликованы**; известно, что это transformer-based; наблюдатели предполагают базу
на открытом LLM или BERT-подобную (TechCrunch через Wikipedia).

Таймлайн «взрыва» класса — пять недель:

## 3. Как это устроено

Общая схема исполнения (по открытым описаниям Clef и Strands):

1. **Prefill-only проход** по state + промпту с вопросами — без генерации токенов.
2. **Параллельный scoring всех допустимых вариантов** каждого вопроса одним проходом.
3. Выход — masked softmax по вариантам; три типа вопросов читаются с одного и того же
   распределения (у Strands это прямо документировано).

### Strands Decider (самая открытая механика)

- Торс предобученного decoder LLM (Qwen3.5-2B-Base; в линейке также Gemma 4),
  **языковая голова выброшена** — модель физически не умеет генерировать текст.
- На её место — **pointer head** на ~1M параметров: hidden state в позиции `<answer>`
  сравнивается со hidden state последнего токена каждого варианта. Один forward pass,
  без decoding loop. Torso адаптирован LoRA rank-16, head работает в fp32.
- В head нет параметров на вариант → ничему не выучить, что «первый вариант обычно
  прав»; число вариантов не ограничено архитектурой.
- Выпуск — model soup из трёх прогонов + пост-калибровка. Данные: 246 678 строк,
  учитель — gemma-4-31B-it; полный рецепт, данные и лицензии источников открыты.
- **Калибровочная гарантия (вендорская): на коротких незнакомых задачах ответы с
  confidence ≥ 0.9 верны примерно в 95% случаев.**

### Clef (Cloudflare)

- База Qwen3.8-27B (Clef) и Qwen3.5-9B (Clef-flash) заморожены; обучены LoRA rank-256 +
  routing head; пост-тренинг: label-smoothed cross-entropy + **Brier loss для
  калибровки вероятностей** + RLCD как вторичная цель (частичный кредит соседним
  уровням шкалы, штраф за расхождение с референсом).
- «Two-stage attention routing»: каждый вариант собирает релевантный контекст, поля
  кросс-аттендятся друг с другом и с исходными данными; lexical prior сохраняет
  семантику опций.
- Clef-omni — на базе Qwen3-Omni-30B-A3B (MoE), принимает аудио/видео/картинки/текст
  в одном вызове.

### Nimble (Bespoke Labs)

- 9B на Qwen3.5-9B; «читает промпт один раз на вопрос и скорит токены ответов напрямую;
  шага рассуждения нет — в этом скорость».
- Обучение на **контрастивных парах**: два примера отличаются одним фактом, который
  переворачивает правильный ответ — модель учится, какое доказательство должно менять
  решение. Пары фильтруются отдельными вызовами моделей (факты согласуются с политикой,
  текст не подсказывает ответ, удаление доказательства делает решающий факт неизвестным);
  лейблы — из проверенных правил в коде.

### Общие приёмы всех вендоров

- Калибровка как отдельная цель потерь (Brier), а не побочный эффект;
- Синтетические данные, построенные из правил/политик;
- Классификация возможностей: модель отвечает «один snap judgment» — суждение, которое
  знающий человек принимает за секунду; сложное раскладывается на вопросы и собирается
  в коде (документация TypeSafe).

## 5. Замеры: что показывают бенчмарки

**Jev Decision Index** (HuggingFace-лидерборд, версия 0.2.1) — профильный лидерборд
класса; в снапшоте на середину октября Clef идёт первым (61.21), всего 73 конфигурации.

**13 публичных датасетов Bespoke Labs** (3 880 решений с человеческими лейблами,
ни одна задача не из тренировочных категорий nimble):

| Модель | Точность |
|---|---|
| Jev 1.13 | 76.0% |
| Nimble 9B | 75.7% (choice 81.6 / boolean 80.2 / score 54.6) |
| Tev1 4B / 0.8B | 73.3% / 63.5% |

**Workflow evals TypeSafe** (evals.typesafe.ai; референс — усреднение GPT-6 Astra и
Fable 5.1; четыре бизнес-воркфлоу: обработка инвойсов, клиентский сервис, инциденты
безопасности, observability агентских трейсов): точность «exact actions» у всех моделей
**57–77%** — честная иллюстрация, что на реальных многошаговых workflows класс ещё
далек от стопроцентной автоматизации. Clef побеждает Jev в 3 из 4.

**10 бенчмарков Cloudflare** (BFCL 98.5–98.8, BANKING77 macro-F1 94.2, CLINC150 97.4,
API-Bank 93.1 и т.д.): Clef ведёт в 7 из 10 против Jev; по латентности clef-flash
опережает всех (медиана 38.8 ms против 524 ms у Jev).

**JevBench** (сторонний бенчмарк класса, 231 задача): Strands Decider 2B v1 — 180/231
(0.779), Brier 0.280; линейка Gemma 4 до 207/231 (26B-A4B). Различия меньше ~10 задач
между одиночными прогонами — внутри шума перетренировки (честная оговорка AWS).

**pplx-decider** (замер Perplexity, 11 бенчмарков): 85.7% против 84.5% у Jev и 74.8%
у базы Qwen3.8-27B; заметный выигрыш на RAGTruth (88.8 vs 77.3) и FinancialPhraseBank.

**Заявления TypeSafe** (вендорские, с самооговорками): 193.6× быстрее и 444.6× дешевле
LLM на своих workflow; «70–500 ms против 3–329 s»; input $42/млрд токенов, output
«too cheap to meter». Компания прямо пишет: workflow созданы её же командой
capabilites — возможен bias; референс из Astra+Fable смещён в сторону OpenAI/Anthropic.

## 6. Независимые проверки и ловушки класса

Данные классу ещё недельного возраста, но независимые тесты уже есть, и они показывают
существенные оговорки:

**1. `choice`-типы не калиброваны.** Тест с монетой (форум OpenAI, пользователь
platypus): при монете 70/30 `predicate`/`noul` за 1000 испытаний даёт оценку 0.70 —
как и положено; `choice` на той же монете возвращает «орёл» с вероятностью **98%** —
модель кладёт почти всю массу на наиболее вероятный вариант вместо оценки постериора.
Плюс: **порядок вариантов меняет выдаваемые вероятности**. Вывод тестировщика:
«не используйте choice-вопросы… и Jev в этом не лучше». Для decision-логики это
серьёзная ловушка: калиброванность нул/да-нет не переносится на multi-option choice.

**2. Confidence ≠ вероятность правоты** — это мера пиковой концентрации распределения;
порог «действуй при 0.9» нужно валидировать на своих данных (Ollama, Strands,
TypeSafe предупреждают единообразно). Strands честно публикует кривую: 0.9+ → ~95%
на их задачах; ниже — подтверждай или спрашивай человека.

**3. Независимость вопросов как архитектурное ограничение.** Ответы не передаются
друг другу; если зависимость реальна — второй запрос в коде. Консистентность взаимо
исключающих ответов (например, два выбора, которые должны согласоваться) тоже
приходится проверять в своём коде (заметки Ollama/Nimble).

**4. Ограничения контекста и объёма.** У nimble каждый вопрос скорится со всем
state и набором вопросов в промпте, который обязан уместиться в **8 192 токена** (при
заявленных 256k в карточке тега); вход никогда не трuncated — оверсайз это 413.
Локальные запросы Ollama: текст+схема ≤ 64 KiB, запрос ≤ 32 MiB.

**5. Модель не объясняет и не дорисовывает.** Она только выбирает из вашего списка —
объяснений, цитат, вложенного JSON не будет; если ни один вариант не подходит, нужен
явный «no match». Для many-way выбора у Jev — двухэтапный scoring с изредка
заметными замедлениями (сами TypeSafe).

**6. Jev — чёрный ящик среди открытых.** Единственный крупный игрок класса, не
опубликовавший ни архитектуры, ни весов, ни бумаги; обучение «исключительно на
синтетике»; benchmark workflow-точки самопроверки. Вся остальная линейка класса
открыта под Apache 2.0 вплоть до полного рецепта воспроизводимости (AWS).

**7. Ранние пользователи OpenAI Decisions API** отмечают: нет кэширования токенов
(классификация выходит экономически менее привлекательной против Responses API),
латентность на изображениях ~0.8 s на медленном соединении, «Luna ~3× чаще даёт
уверенно неправильные ответы на тонких суждениях, чем Jev» (анекдотика, несколько
сотен вопросов, пользователь jefff — при этом «Jev быстрее (0.3 s vs 1.6 s медиана),
дешевле в 2–3× и точнее на judgment-heavy задачах»).

**8. Точка приложения — только «snap judgment».** Вендоры единодушны: аналитика
«определите лучший курс действий из этого сообщения» — это не задача класса; она
должна раскладываться на мелкие вопросы с комбинацией в коде. Стратегия — не умнее,
а декомпозиция.

## 7. Функция класса: зачем и где применяют

**Принципиальная роль в системе:** decision-модель — это «умный if-оператор» /
«frontier-intelligence function call» между LLM и классическим классификатором:
дешевле и быстрее LLM, гибче классификатора (без обучения под метки). Формулировка
AWS: класс работает «для проблем между LLM и традиционными классификаторами».

Типовые применения (по документации всех вендоров):

- **Роутинг** — тикетов, запросов, моделей (какая LLM должна ответить на промпт);
- **Выбор инструмента и проверка аргументов агента** — gate перед исполнением
  tool-call («может ли этот вызов навредить?», «заполнены ли обязательные поля?»);
- **Гейтирдворды и guardrails** — safety/moderation, детект PII, проверка groundness;
- **Оценка и грейдинг** — rubric-скоринг выходов других моделей, evals за копейки;
- **Триаж и классификация** — срочность, команда, категория документа/домена;
- **Применение политик** — «подписывает ли этот кейс под правило X из политики»;
- **Мультимодальные решения** — чеки, формы, скриншоты, схемы установки (Clef-omni:
  фото + аудио работы устройства + видео вентилятора в одном вызове);
- **Real-time** — игры и реактивные петли: демки TypeSafe Doom (~10 запросов/сек,
  ~$7/час), Wikiracing (выбор среди сотен–тысяч ссылок), Pac-Man 91 ms/решение
  (Ollama, M5 Max).

Паттерн композиции: **speculative fan-out** — задавать все вопросы, которые могут
понадобиться, одним вызовом (13 вопросов в одном вызове = 11.5× дешевле и 9.6×
быстрее, чем 13 вызовов, TypeSafe cookbook); **composite scoring** — сложная оценка =
несколько score-вопросов, взвешенных в коде (веса меняются в коде, а не в промпте);
**hybrid agent** — LLM принимает сложные решения, decider — рутинные.

### Задокументированные внедрения

**Jack & Jill** (маркетплейс талантов на AI-агентах; 5 000+ компаний, 400 000+
специалистов, $60M раундов) — кейс TypeSafe:
- Заменили **Gemini 3.1 Flash Lite на 100% вызовов** в ключевом этапе скрининга
  кандидатов за **10 дней** от первого теста до прода.
- **−88% стоимости** ($0.755 → $0.092 за 1 000 проскоренных кандидатов; input
  $0.042 vs $0.25, output бесплатный), **2× быстрее** (медиана скрининга роли
  20.3 s → 10.3 s), качество не просело: recall «winners» 93.9% → 94.6%, AUC
  0.924 → 0.933 (замер на 150 живых ролях).
- Экономия **$265K/год** на текущих объёмах, **~$500K** с учётом роста; Jev
  развернут в 15+ workflow; проверка профиля после онбординга 3.6 s → 0.2 s.

**Cloudflare (внутренние использования Clef):**
- Threat Intelligence: классификация доменов через Browser Run за 2.2 s
  (95% — fashion, 85% — ecommerce, <1% — phishing) против 4.7 s у самого быстрого
  собственного LLM (gpt-oss-120b), который вернул только две категории;
- репозиторий cloudflare-docs: мгновенный детект и автозакрытие spam-issues;
- EmDash (их CMS): модерация плагинов на фишинг;
- DLP-команда: сканирование на PII (госудокументы);
- RL-продукт дообучения Clef на собственных размеченных данных клиентов
  (15 лет сетевых данных Cloudflare как сырьё для fine-tuning).

**AWS:** Strands Decider встроен в Strands Agents SDK как `before_tool_call`
interception — два да/нет решения гейтят вызов инструмента (агент спрашивает город,
а не угадывает).

Драйверы: (1) отсутствие автогенерации → нет output-счёта и кэша промптов не требуется

и приватен — Strands 2B переобучается за 11 часов на одном RTX 3090.

## 9. Почему это класс, а не продукт

- **Интерфейс стандартизировался за две недели:** `state` + `questions` + три типа →
  Jev API стал совместимым контрактом (Ollama `/v1/systemone`, Cloudflare, Strands,
  TypeSafe SDK, OpenRouter, LangChain). Можно менять вендоров по model ID.
- **Открытая линейка против проприетарной:** 4 из 5 крупных поставщиков (Cloudflare,
  AWS, Perplexity, Bespoke) отдали Apache 2.0; Jev и OpenAI — проприетарные hosted.
- **Скорость итерации отрасли:** Cloudflare: «в пятницу вечером решили сделать
  decision-модель, выходные обучили, в четверг запустили»; класс породил
  десяток моделей за 32 дня от анонса до конкуренции в лидербордах.
- **Конкуренция уже по всем осям:** точность (Jev/Clef/pplx), латентность
  (clef-flash 38.8 ms, Laya 5.8 ms), модальности (Clef-omni), открытость (Strands),
  цена (Clef-flash < Jev), экосистема (Bedrock AgentCore, Workers AI, Ollama).

## 10. Чем этот класс НЕ является

- **Не «решением» в корпоративном смысле** — это инференс-примитив. Платформы
  decision management (FICO, Aera, DMN/BRMS) — другой уровень: там моделируются
  процессы принятия решений, владение, комплаенс; decision-модель класса System One
  — просто ещё один скоринговый узел внутри такого контура (или вместо ручного
  if-блока).
- **Не LLM со structured output:** JSON-режим LLM всё равно генерирует и может
  «уйти с рельсов»; здесь генерация физически исключена, а типобезопасность
  математически гарантирована схемой.
- **Не замена классификатору в узкой нише:** если метка стабильна и данные есть —
  fine-tuned BERT по-прежнему дешевле и точнее; сила класса — zero-shot по
  произвольным, меняющимся меткам.
- **Не System 2:** модель не рассуждает и не анализирует «всё сообщение и лучший
  курс действий»; её функция — быстрое структурированное суждение, всё остальное
  собирается в окружающем коде.
